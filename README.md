# SportRace – дипломна версия

Уеб базирана информационна система за организация и управление на спортни събития и състезания. Приложението позволява поддръжка на участници, спортни регистрации, стартови списъци, резултати и статистически справки.

Разработено е с C#, ASP.NET Core Web API, Razor Pages, Entity Framework Core и MySQL. Интерфейсът използва Bootstrap и е на български език.

## Изисквания

- .NET 10 SDK – проектите използват `net10.0`.
- Работещ MySQL сървър и потребител с права за създаване и промяна на базата.
- Интернет връзка при първоначалното възстановяване на NuGet пакетите.
- Браузър за работа с приложението.

В предоставения проект са зададени Entity Framework Core 9.0.20 и Pomelo.EntityFrameworkCore.MySql 9.0.0.

## Инсталация и стартиране

### 1. Подготовка на проекта

Разархивирайте проекта и отворете терминал в папката, съдържаща `SportRace.slnx` и подпапките `SportRace.API` и `SportRace.Web`.

Възстановете пакетите:

```bash
dotnet restore SportRace.slnx
```

### 2. Настройване на базата данни

Стартирайте MySQL. В `SportRace.API/appsettings.json` задайте своята връзка в `ConnectionStrings:DefaultConnection`. Например:

```json
"ConnectionStrings": {
  "DefaultConnection": "Server=localhost;Port=3306;Database=SportRaceDb;User=YOUR_MYSQL_USER;Password=YOUR_MYSQL_PASSWORD;"
}
```

Заменете потребителя и паролата с тези за вашия MySQL сървър. Запазете останалите настройки във файла.

При първоначална настройка инсталирайте инструмента за EF Core, ако липсва:

```bash
dotnet tool install --global dotnet-ef --version 9.0.20
```

Приложете наличните миграции:

```bash
dotnet ef database update --project SportRace.Infrastructure --startup-project SportRace.API
```

Използвайте наличните миграции, без да създавате нова `InitialCreate`. Преди промени по съществуваща база с важни данни направете резервно копие. API не прилага миграциите автоматично при стартиране.

### 3. Стартиране на API

В първия терминал изпълнете:

```bash
dotnet run --project SportRace.API --launch-profile http
```

API работи на `http://localhost:5012`.

### 4. Стартиране на сайта

Във втори терминал, от същата основна папка, изпълнете:

```bash
dotnet run --project SportRace.Web --launch-profile http
```

Отворете `http://localhost:5224` в браузъра. По време на работа трябва да са стартирани MySQL, API и уеб приложението.

### 5. Демонстрационен вход

- Електронна поща: `admin@sportrace.local`
- Парола: `Admin123!`

След като таблиците са създадени, API добавя този администратор при стартиране, ако няма потребител със същата електронна поща. Съществуващата парола не се нулира автоматично.

Данните са за локална демонстрация. Преди реално публикуване премахнете автоматичното създаване на този профил или го заменете със защитена процедура за първоначална настройка.

## Реализирани модули

- начална страница и публичен преглед на състезанията;
- подробна информация за избрано състезание;
- регистрация на потребителски профил, вход и изход;
- създаване, редактиране и изтриване на състезания;
- управление на участници и контактни данни;
- поддръжка на дисциплини, категории и възрастови групи;
- записване на участници за състезания през административната част;
- управление на статуса на спортните регистрации;
- генериране и публикуване на стартови списъци;
- въвеждане на време, наказателни секунди и признак за финиширане;
- изчисляване на крайно време и автоматично класиране;
- статистика и справки по състезания.

## Потребителски роли и достъп

Посетител без вход може да разглежда началната страница, списъка със състезания и техните подробности, както и да създаде профил.

Новите профили получават роля `Participant`. В текущата версия няма лични страници „Моите регистрации“ и „Моите резултати“, нито самостоятелно записване за състезание. Регистрацията на профил и записването на участник за състезание са отделни действия.

Ролите `Administrator`, `Organizer` и `Judge` имат достъп до общата административна област. В нея са разположени и стартовите списъци, резултатите и статистиката. Между тези три роли все още няма отделни ограничения за всяко административно действие.

## Примерна последователност за работа

1. Влезте с демонстрационния администратор.
2. Създайте състезание и попълнете неговите данни.
3. Добавете дисциплина, категория и възрастова група.
4. Добавете участник.
5. Създайте спортна регистрация, като свържете участника със състезанието и съответните справочни данни.
6. Генерирайте стартов списък, прегледайте го и го публикувайте.
7. Въведете резултат за регистрацията.
8. Проверете крайното време, позицията в класирането и статистическата справка.

## Стартови списъци и резултати

При генериране на стартов списък се включват регистрациите за избраното състезание, които не са със статус `Rejected`. Стартовите номера се задават последователно. Планираните часове са през пет минути, считано от текущия UTC момент на генериране.

Крайното време се изчислява като измерено време плюс наказателните секунди. Например `01:03:00` с наказание от `15` секунди дава `01:03:15`.

Класирането се преизчислява в рамките на еднакви състезание, дисциплина, категория и възрастова група. Завършилите се подреждат по крайно време, а незавършилите получават позиция `0`. При равни времена няма отделно правило за споделено място.

## Структура на решението

| Проект | Предназначение |
| --- | --- |
| `SportRace.Domain` | Същности и потребителски роли. |
| `SportRace.Application` | Отделен проект, предвиден за приложна логика; в тази версия е почти празен. |
| `SportRace.Infrastructure` | Контекст на базата данни, конфигурация на връзките и миграции. |
| `SportRace.API` | HTTP контролери, обработка на данните и основни бизнес правила. |
| `SportRace.Web` | Razor Pages, форми, навигация и потребителски интерфейс. |

## Настройки и ограничения

- Адресът на API е зададен в `SportRace.Web/Program.cs`. Част от страниците също използват абсолютни адреси към `http://localhost:5012`. При смяна на порта трябва да се обновят всички такива адреси.
- Надписът „Предстоящи състезания“ не означава автоматично филтриране по бъдеща дата в API.
- Признакът за публикуване на събития и стартови списъци не осигурява самостоятелно ограничаване на четящите API заявки.
- Уеб административните страници са защитени с проверка на ролята. API няма завършено самостоятелно удостоверяване и разрешаване на достъпа и изисква доработка преди публично използване.

## При проблем със стартирането

- При грешка за връзка с базата проверете дали MySQL работи и дали адресът, портът, потребителят и паролата са правилни.
- При липсваща таблица `Users` проверете дали миграциите са приложени към правилната база.
- Ако страниците не зареждат данни, проверете дали API работи на `http://localhost:5012`.
- Ако входът с демонстрационната парола е неуспешен, проверете дали профилът вече съществува с друга парола.
